# 제작 산출물 보관 정책 — deliverables-v2

사용자 지시: 전체 작업 폴더를 보관하지 않는다. 완성된 영상과 편집·재사용에 필요한 제작 산출물만 남긴다.

## 남길 것
- 최종 MP4, 대본, 스토리보드
- 캐릭터 시트/캐릭터 바이블
- 최종 선택된 샷 이미지 (탈락한 버전 제외)
- 음성 WAV, 자막 SRT/타임스탬프, 편집 설정
- 최종 이미지 프롬프트 통합 문서
- 작은 최종 manifest/QA 요약/권리·승인 식별 기록

## 제외·정리할 것
- `.history`, 모델 대화/요청/응답 원문, 디버그 로그
- 재시도용 캐시, 임시 ZIP, 검수용 합성 보드·샘플 프레임
- 사용하지 않은 이미지 버전, 렌더 전처리용 중복 이미지
- 개별 요청·비용 로그의 산출물 폴더 복제본

DB의 업로드 ID, 승인, 예산·결제 중복 방지 및 완료 상태는 별도 시스템 기록이다. 사용자 산출물 ZIP에 실행 로그를 복제하지 않는다. 인증 파일/키는 보관 대상이 아니다.

## 삭제 안전 조건
- 제작 중이거나 실패/결과 미확정인 작업은 정리하지 않는다.
- 현재 구현의 보수적 정리 조건은 실제 발행 확인(PUBLISHED) + 검증된 Drive 보관(ARCHIVED) + 같은 story/render/final SHA이다.
- 보존 대상 파일이 모두 존재하는지 먼저 검사한다. 심볼릭 링크나 최종 영상 SHA 변경이 있으면 삭제하지 않는다.
- dry run이 기본값이다. 삭제는 명시적 apply 호출에서만 수행하며 DB/볼륨 전체를 지우지 않는다. 최종 사용 파일과 사용자 추가 메모는 유지한다.


## 배포 상태
설치 프리뷰이며 운영 승인/기존 산출물 교체/자동 삭제 연결은 별도 검증이 필요합니다.
