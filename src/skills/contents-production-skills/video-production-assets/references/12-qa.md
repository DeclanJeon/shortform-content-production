# 제작 검수·수정 라우팅

## 입력과 산출물
입력: 브리프와 실제 산출물, 버전, 목표 형식

산출물: 근거 있는 검수 결과와 수정 순서

## 실행 절차
1. 각본·스토리보드·프롬프트·애니매틱·러프컷·최종 파일 중 검수 대상을 명시한다. 각 관찰의 출처를 직접 검사 / 사용자 제공 관찰·기록 / 도구 출력 / 추론으로 구분한다. 사용자 보고를 직접 검사 결과처럼 표현하지 않는다. 미리보기나 측정이 없는 항목은 미검증으로 남긴다.
2. 서사 인과 / 목표·연기 / 시각·촬영 / 조명 / 움직임 / 편집·사운드 / 사실·형식을 적용 가능한 범위에서 검사한다.
3. 문제마다 artifact_id·scene_id·shot_id·타임코드 또는 문서 위치를 기록한다. 문제→관객 영향→수정→재검증 기준으로 쓴다.
4. 필수 메시지 누락·확인되지 않은 주요 주장·길이 오류·깨진 에셋 참조를 blocker로 분류한다. 인상 개선은 major 또는 minor로 구분한다.
5. 영상의 리듬·동적 움직임·음악 싱크가 요청 기준이면 샷 단독 표본을 완성 시퀀스 통과 근거로 대체하지 않는다. 전체 재생과 실제 믹스 검사는 [완성 시퀀스 QA](21-generated-video-qa-retry.md)를 따른다.
6. 원인을 수정할 담당 모듈로 되돌린다. 각본이 바뀌면 관련 샷·연기·조명·프롬프트·편집의 stale 상태를 설정한다.
7. 구조 검증 통과를 작품 품질의 증명으로 해석하지 않는다. 실제 파일 없는 최종 승인, 가상의 렌더링·청취·성능 점수를 만들지 않는다.
8. 상세 콘티·전체 스토리보드 시트·제공 콘티 QA에는 [완전한 보드 계약](storyboard-contract.md) §5–6을 필수 적용한다. 실제 clean 컷 전수를 설명/음향 없이 이야기 순서로 검수해 읽힌 사건·인과/정보·감정과 승인 시놉 전체 비트를 대조한다. 텍스트 설계 검수와 실제 이미지 판정을 구분한다. KEEP/FIX/미검증을 stable ID로 나누고 수정 이유·최소 방법·보존 요소·추가 준비물·담당/의존성·소요시간 범위와 근거·재검수 조건을 기록한다. 근거 없는 시간은 미정과 필요한 측정으로 적는다. 허용된 수정은 수행→버전 갱신/stale→관련 컷과 전체 순서 재검수하며 새로운 지출/범위는 별도 승인을 받는다.

## 완료 조건
요청 범위에 있는 모든 blocker가 해결됐는가? 계획 검수와 미디어 납품 검수를 구분했는가? 실제 확인 항목과 미검증 항목을 구분했는가?

## 근거와 적용 범위
이 파일의 검사 순서·blocker/major/minor 분류·KEEP/REBUILD/DROP·수정 라우팅·회고 형식은 패키지가 정한 운영 설계이며, 특정 서적에서 직접 도출한 QA 규격으로 인용하지 않는다.
검수에 사용하는 서사·연기·시각·편집 craft 원리는 해당 소유 모듈의 주장별 출처를 따로 따른다. `sources.md`의 자료 목록만으로 이 파일 전체가 서적에서 검증됐다고 말하지 않는다. 근거 질의에는 `이 파일 §정확한 제목`과 위 분리 문장을 인용하고, 검사하지 않은 품질/효과 또는 연결 근거가 없는 외부 craft 주장은 `[BASIS-UNSTATED]`로 남긴다.

## 판정
pass / pass_with_notes / needs_revision 중 하나와 검사 범위를 기록한다. 미디어를 요청받은 경우 주요 미디어 항목이 미검증이면 pass로 판정하지 않는다. 무음 작품의 음성 명료도, 등장인물 없는 설명 영상의 배우 리허설 등은 N/A다.

## 심화 참조
실제 생성 매체의 검사 순서·패스·실패→수정 매핑·재시도 사다리는 [생성 영상 QA·재시도](21-generated-video-qa-retry.md), `../assets/generated-qa-report-template.md` 사용. 콘셉트·구조 품질 게이트는 아래 내용 품질 판정과 [콘셉트·감정·유지](16-concept-emotion-retention.md)를 따른다.

## 내용 품질 판정
칭찬이 아니라 개선 또는 거절을 위해 판정한다. 고칠 수 있는 실행 문제와 약한 근본 전제를 구분한다.

1. 요청 목적과 산출물 모드를 재구성한다: 정보 전달·기록·서사·오락·설득·분위기 중 적용되는 기준만 사용한다. 중요 목적이 미정이면 확인하되 모든 작업에 판매 약속·갈등·감정 반전을 강제하지 않는다.
2. 차단 게이트는 요청 충족, 사실/출처 정합, 핵심 인과·정보 순서, 실제 제작 가능성과 해당하는 결말/보상이다. 서사·촬영 기준을 일반 원고의 의무로 바꾸지 않는다.
3. 적용되는 강도 기준을 검사한다: 독창성·감정·기억·주의·시각·소리·플랫폼·제작 일관성. 창작 판정을 실제 유지율/전환율 측정이나 사용자 수락으로 보고하지 않는다.
4. 모든 blocker를 보고하고 가장 영향 큰 개선점을 근거·구체적 수정과 함께 우선순위로 적는다. 사소한 마무리는 별도로 둔다.
5. 구분한다: KEEP(근본 작동, 실행 다듬기) / REBUILD(목적 적합, 구조 수리 필요) / DROP(핵심이 브리프를 충족할 수 없음).

임의 가중 평균으로 치명적 결함을 숨기지 않는다. 하나의 차단 게이트 실패가 rebuild/drop을 정당화할 수 있다.

## 레퍼런스 의도 대조 (해당 작업만)

승인된 레퍼런스 분석·프로젝트 스타일 브리프와 결과의 실제 버전을 입력받는다. [레퍼런스 분석](25-reference-video-analysis.md)의 이전 체인과 [스타일 브리프](01-brief.md)의 적용 요구를 검사 기준으로 쓰고, 원본의 구체적 표현을 얼마나 복제했는지로 판단하지 않는다.

1. 정보 공개/리듬, 샷/카메라, 시각 룩, 사운드, 서사·감정 효과 중 의뢰한 축만 비교한다. 다른 길이·소재에서는 의도된 비트의 기능과 순서를 비교한다. 원본/결과에서 관찰된 시각 자체는 승인된 목표 시간이 아니다. 시간 오차는 승인된 제작 요구가 목표 시각을 명시한 경우만 판정한다.
2. 각 요구를 **충족 / 차이·수정 필요 / 미검증 / N/A(사유)**로 기록한다. 프레임·재생·청취 또는 사용자 제공 기록의 위치와 검사 범위를 적는다. 서사·감정 효과는 해석임을 밝히고 실제 시청자 반응으로 표현하지 않는다.
3. 요구한 음향이 없거나 보지 못한 구간은 N/A가 아니다. 요구 미충족 또는 미검증으로 남긴다. 원본/결과 파일이 없으면 가능한 텍스트·사용자 기록 대조만 수행하고 실제 미디어 판정을 보류한다.
4. 문제→관객 영향(해석)→최소 수정→실제 재검증 기준 순으로 우선순위를 정한다. 숫자 유사도·백분율·가중 평균이나 이를 통한 자동 통과/재생성 기준을 사용하지 않는다. 기존 정성 QA 판정과 사용자 승인은 별개이며 수정 제안은 추가 실행 허가가 아니다.

## 요청 기반 제작 회고

사용자가 회고를 요청했을 때만 해당 프로젝트에서 실제 확인한 결과와 시도 기록을 정리한다. 기본 납품에 회고 문서를 강제하지 않는다.

| 항목 | 내용 |
|---|---|
| 잘된 선택·실패 | 실제 버전/위치·검사 근거와 영향 |
| 원인·교훈 | 근거로 확인된 내용과 원인 가설을 분리 |
| 적용 범위 | 이번 프로젝트의 조건, 다른 소재에 적용할 때 확인할 조건 |
| 다음 작업 제안 | 유지/변경할 선택과 실제 검증 방법; 미검증 개선은 제안 |

단일 결과의 성공을 일반 법칙이나 성과 보장으로 승격하지 않는다. 회고는 채팅 또는 요청된 프로젝트 기록으로 남기며, 공용 스킬·브랜드 프로필의 자동 수정·승격·백그라운드 학습을 수행하지 않는다. 스킬 변경은 별도의 명시적 편집 요청 범위다.

## 카메라 무빙 집중 검사
카메라 워킹/무빙·렌즈/초점·공개 타이밍·추적·흔들림의 결과 검수에는 [카메라 무빙 QA](27-camera-motion-qa.md)와 `../assets/camera-motion-qa-template.md`를 적용한다. 실제 재생과 문제 구간의 증거를 갖추고 일반 생성 QA와 중복된 원장을 만들지 않는다.
