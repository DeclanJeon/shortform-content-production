# 참조 기반 생성 제작의 실무 인계

기존 05·11·14·18·20·21·22·15 모듈의 조건부 심화다. 새 스킬·새 원장·특정 드라마 제작 규격이 아니다. 현재 산출물에 필요한 절만 적용하며 단일 원고/텍스트 요청을 전체 제작·이미지·영상·음성 실행으로 확대하지 않는다.

### 제작 단위를 혼동하지 않는다

GUIDE-01 p6의 구분을 적용한다. 에셋은 재사용할 대상/자산, 시트는 그 속성을 설명하는 문서다. 씬은 사건의 시공간/상황 단위, 샷은 하나의 카메라 시점으로 보여 주는 단위, 비트는 행동/정보의 변화다. 클립은 서비스가 출력한 파일이므로 **한 클립≠한 샷**일 수 있다. 같은 계획의 개별 결과는 각각 다른 테이크다. 작품에서 채택한 설정/사건과 기준 파일(마스터)은 우연한 생성 결과나 최신 파일과 구별한다. 샷/클립 관계는 기존 shot ID와 결과 asset/편집 인계에 적고 새 스키마/enum을 만들지 않는다. 단위 설명만 요청받고 원장 ID가 없으면 역할명과 ID 미배정으로 답한다. 임의 SH01 등을 실제 할당된 ID처럼 제시하지 않으며 예시가 필요하면 비정본 예시로 표시한다.

## 출처와 우선순위

사용자 제공 제작 경험서 **GUIDE-01**, PDF pp4–101에서 재사용 가능한 공정을 일반화했다. 페이지별 범위·채택/기존 유지/제외 내역은 [추출 대조표](guide-01-extraction.md), 파일 지문과 스캔 범위는 [스캔 기록](guide-01-scan.json)에 있다. PDF 안에서 소개한 원본 영상·음성·Blender 파일은 이번 검토에 제공되지 않았다. 책 속 정지 캡처·설명·입력 화면은 실제 생성/동작/발음 성공의 증거가 아니다. 공급자 기능/가격/개인 체감 성능도 현재 검증값이 아니다.

사용자 SSOT·요청·현재 패키지 계약·실제 도구 지원을 우선한다. 본 절의 운영 규칙은 경험서의 일반화이지 효과 검증·성공 보장이 아니다. 기존 이미지 실행 경로·비용/승인·단일 기록자·스키마·판정 enum은 바꾸지 않는다. 특히 전체 image_backed 패키지의 **인물당 Sheet A 7뷰 요구는 유지**하며, 아래 최소 입력 원칙은 그 패키지 요구를 면제하지 않는다. 움직이는 프리비즈/애니매틱은 별도 실행 승인이 필요하다.

## R1. 참조는 파일 전체가 아니라 속성별 계약이다

적용: 둘 이상의 참조, 통합 시트, 지도, 프리비즈, 직전 클립을 생성 입력으로 옮길 때. 근거: GUIDE-01 pp38–39, 64–69, 74–75, 80–82.

1. 기존 승인 에셋의 ID·버전·실제 파일·가능한 해시를 확인한다. 같은 파일명이라도 내용을 열어 현재 상태와 원본 크기를 대조한다. 해시만으로 의미/검수 통과를 주장하지 않는다.
2. `assets/11-ai-handoff-template.md`의 역할표에 **가져올 속성 / 제외할 속성 / 충돌 시 우선 기준**을 쓴다. 한 속성에는 우선 기준 하나를 지정한다. 얼굴은 A, 의상은 B라면 B의 얼굴은 제외한다. 날짜가 최신이라는 이유만으로 모든 속성의 정본을 바꾸지 않는다.
3. 흔한 분업:
   - 인물 시트: 얼굴·머리·체격·해당 의상. 패널 배치·흰 배경·라벨·다른 상태는 제외.
   - 장소 시트: 구조·재질·광원. 우연히 포함된 인물과 고정 카메라 구도의 복제는 제외.
   - 소품 시트: 형태·재질·현재 상태. 다른 개폐 상태·효과 발동·설명 글자는 제외.
   - 동선도: 위치·경로. 화살표·문자·도형 색상은 제외.
   - 직전 채택 클립: 실제 종료 포즈·소유·의상·진행 방향. 앞 동작 재연과 불필요한 원본 소리는 제외.
   - 프리비즈: 지정 카메라·컷·블로킹·타이밍. 대역 얼굴·체형·색상·플라스틱 질감·임시 음향은 제외.
4. 옛 지도와 새 프리비즈가 충돌하면 전체 파일의 우열이 아니라 속성별로 해결한다. 예: 소품 위치는 승인 배치, 시작 자세는 채택 클립, 새 카메라는 승인된 카메라 명세. 미해결 충돌은 실행 blocker다. **관측된 오류를 자동 정본으로 승격하지 않는다.**
5. 업로드 뒤 실제 슬롯/태그를 파일과 다시 맞춘다. 첨부 삭제·순서 변경 시 역할표와 제출문을 모두 재대조한다. 미업로드 파일에 태그만 써서 참조가 생겼다고 하지 않는다. 음성 파일이 없으면 오디오 참조 태그도 없다.
6. 자동 프롬프트 보정이 켜져 있으면 **클라이언트가 실제 보낸 전체 요청문**과 옵션을 기존 이력에 보존하고, 공급자가 보정/확장한 **변환 후 본문**은 별도로 기록한다. 변환 후 본문만 비노출이면 그 항목만 `NOT_EXPOSED`다. 이를 이유로 실제 요청문 스냅샷을 생략하거나 숨겨진 변환문까지 확인했다고 하지 않는다. 실제로 보낸 요청문 자체가 없으면 기존 프롬프트/SSOT 소비 증거 요건을 충족했다고 보고하지 않는다.

통과: 활성 참조의 파일→슬롯→속성→우선 기준이 모두 연결되고 상충 지시가 없다. 역할표는 버전이 있는 인계 문서이며 별도 에셋/승인 원장이 아니다.

## R2. 사람용 시트와 생성 입력용 뷰를 나눈다

적용: 캐릭터·의상·소품 시트의 제작/확장/입력 선택. 근거: GUIDE-01 pp30–43.

1. 신규 정체성 탐색과 기존 인물 확장을 구별한다. 신규 후보는 조명·구도·의상을 가능한 한 고정하고 얼굴형 등 비교 축을 한 번에 하나 정한다. 승인 인물은 새로 캐스팅하지 않는다. 신원·해부·설정의 필수 조건을 먼저 검사한 후보끼리 제작/장면 적합성·선호를 비교한다. 높은 미감/평균 점수로 다른 얼굴·설정 위반을 상쇄하지 않는다(GUIDE-01 p32).
2. 얼굴 기준→체격/전신→의상 구조→필요 방향→필요 표정/접촉 순으로 의존성을 확인한다. 전체 시트의 필수 뷰는 기존 계약대로, 추가 표정·상태·접촉 자료는 해당 샷의 필요에 따라 준비한다.
3. 의상은 색 외에 여밈 방향·겹침·허리끈 높이·소매 끝·겉감/안감·신발을 설명한다. 미관측 후면을 새로 설계하면 `proposal`로 두고 승격 전 검토한다. 기본 신원, 기본 의상, 환복/젖음/손상 상태를 부모 버전과 델타로 분리한다.
4. 통합 시트와 각 뷰의 원본을 연결해 보관한다. 생성 입력은 샷에 필요한 **동일 인물·동일 상태**의 뷰를 우선한다. 통합 시트를 쓰면 여러 인물/분할 화면이 아니라 한 인물의 다른 뷰임을 선언하고 패널 배경·글자 전사를 제외한다.
5. 시트별 **답할 수 있는 질문 / 답할 수 없는 질문**을 적는다. 얼굴 삭제본은 신원 검증 불가, 머리가 잘린 뷰는 전체 비율 검증 불가, 중립 표정은 발화 시 신원 유지 검증 불가다. 없는 정보를 복원했다고 하지 않는다.
6. 축소로 전체 배치·잘림, 원본 크기로 얼굴/손·의상 경계, 뷰 간 번갈아 보기로 구조를 검사한다. 전신 뷰는 같은 바닥선·표시 축척으로 비교하고 실제 키 관계와 화면 표시 배율을 혼동하지 않는다.
7. 좌우는 인물 기준/화면 기준을 명시한다. 매듭·가방 등 비대칭 앵커 하나를 전후면에서 추적한다. 회전/카메라 방향을 먼저 확인한 뒤 거울 반전 오류를 판단한다.
8. 두 인물의 투샷은 각 신원·키 관계·의상 분리를 먼저 확인하고, 필요한 경우 시선 교환·접촉을 추가한다. 시트·포즈 계획은 실제 접촉/하중의 증거를 대신하지 않는다.

독립 관리할 소품은 반복 식별·이야기 단서·손 조작·클로즈업·상태 변화의 필요로 고른다. 장식물 전부를 등록하지 않는다. 조작 소품에는 소유자·상대 크기·개폐/효과 상태·그립·금지 변형을 적고, 집기 전/접촉/이후의 수와 최종 소유자를 검사한다. 흰 배경은 투명 알파가 아니다.

소품 형태를 새로 탐색할 때는 필요한 단일 상태를 중립 배경에서 먼저 구분하고, 인물·손·배경 사건·효과를 동시에 요구해 형태 확인을 흐리지 않는다. 이후 필요한 방향/조작 상태/접촉을 확장한다. 기본 의상에 붙박이인 장비와 이번 행동에서 잠깐 든 물체는 분리하고, 승인 디자인에 없는 장비를 자동 추가하지 않는다(GUIDE-01 pp41–43). 이는 작성/비교 순서이며 추가 이미지 실행 승인이 아니다.

복잡한 생물은 몸통/관절 연결·바닥 접촉점·상대 스케일·이동 방향·공격/동작 범위와 상대의 진입선을 분리한다. 탈것은 탑승 위치·하중을 받는 지점·진행 방향을 외형과 별도로 적는다. 효과는 **발동 전→시작→지속→소멸**과 소멸 뒤 남을/사라질 결과를 구분한다. 크리처 정면 이미지 한 장은 관절 가동/접촉을 검증하지 않는다. [21 모션/VFX](21-generated-video-qa-retry.md)의 기존 모션·레이어 템플릿과 필요 시 [26 상태 인계](26-state-causality-continuity.md)를 쓴다(GUIDE-01 p43). 근거 없는 관절 각도·질량을 발명하거나 물리/리깅 시뮬레이션을 자동 실행하지 않는다.

군중은 [20의 군중 규칙](20-visual-mode-ssot.md)에 연결한다. 사건상 정확한 인원수와 배경 밀도를 구별하고, 주요 군중/먼 배경의 식별 수준·진출입 범위·주인공 통로·군중 참조에서 제외할 주인공 신원을 명시한다. 하나의 군중 시트를 매번 복제하거나 필요 없는 개인별 Full SSOT를 만들지 않는다(GUIDE-01 p43).

공유본은 원본과 별도로 만들고 얼굴 삭제를 요청받았으면 작은 전신 얼굴·썸네일·HTML·PDF 첨부까지 점검한다. 이는 해당 자료의 공개 범위 관리이지 모든 공개물에서 얼굴을 지우라는 규칙이 아니다. 삭제본을 원래 신원의 생성 참조로 사용하지 않는다.

## R3. 공간·연기·카메라가 담당하는 변화를 분리한다

적용: 같은 장소의 역방향, 상호작용, 감정 키 비주얼, 프리비즈 인계. 근거: GUIDE-01 pp44–63, 77–89.

- 장소의 **외형 기준**과 **공간 관계**를 분리한다. 가능한 경우 인물 없는 장소 마스터, 입출구·랜드마크·바닥 높이·주광원 관계를 둔다. 다른 방향은 원본 이미지의 좌우 반전이 아니다. 장소 시트 여러 뷰만으로 정확한 3D 공간 검증을 선언하지 않는다.
- 카메라가 움직이는 것과 인물이 움직이는 것을 따로 적는다. 공간 방위, 인물 좌우, 화면 좌우를 구분한다. 역방향 샷에서도 실제 광원은 공간에 고정하고 카메라가 보는 방향을 바꾼다. 상태 변형은 날씨/빛만 바꾸는지 건축까지 바꾸는지 비교한다.
- 감정은 **자극→최소 반응→억제/선택→후속 행동**으로 풀어 쓴다. 원문의 완료/의식/위치 상태를 약화하거나 임의 회복시키지 않는다. 짧은 샷의 핵심 전환 하나를 먼저 읽히게 하고 대사 특정 지점에 반응이 걸리면 정확한 발화 원문을 보존한다.
- 키 비주얼은 대표 순간·시선 중심·광원·재질/깊이를 정한다. 신원 시트·동작 콘티·시간 검증의 대체물이 아니다. 정보 우선순위는 사건/정체성→핵심 행동→빛/재질→선택 장식이다.
- 카메라·렌즈·리그 이름은 화면 의도를 전달하는 어휘다. 무엇이 선명해야 하고 무엇을 가리면 안 되는지, 시작 위치/방향→경로→정지 지점을 덧붙인다. 전경 가림은 손·얼굴·접촉을 지우지 않아야 한다. 돌리와 줌은 위치 변화/시차 유무로 구별한다.
- f-number와 T-stop을 혼동하지 않는다. T-stop은 투과를 반영한 노출 표기이며 T값 하나로 심도를 계산하지 않는다. UI가 f만 받으면 T 제어가 있다고 쓰지 않는다. 특정 장비명·T값의 생성 우월성은 채택하지 않는다.
- 프리비즈의 대역별 인물 대응과 가져올 움직임/제외할 외형을 R1에 기록한다. 대응 시점별로 배치→접촉/지지→카메라 경로→컷→끝 상태를 비교한다. 무음 동선 검사와 필요 시 음성/반응 타이밍 검사를 나눈다. 연속 프레임·청취 없는 정지 렌더는 동작/연기/음성 검증이 아니다.
- 중요한 행동 뒤 안정된 결과와 편집 핸들이 필요한지 계획한다. 불안정한 접촉은 인서트/반응 커버리지로 재설계할 수 있으나 관객에게 필요한 소유 이전·원인 동작을 삭제해 오류를 숨기지 않는다.
- 컷 전환은 **새 정보·행동·반응·감정·시선 중 하나의 실제 변화**를 근거로 한다. 컷 수나 컷 길이의 목표값을 먼저 정하지 않는다. 어떤 길이 프로필(구간 배분·컷 리듬·감정 유지 시간)을 쓰더라도 그것은 예시이며, 그 구간 안에 카메라가 보낼 정보나 행동이 남아 있는지 확인한다.
- 감정 구간의 카메라는 움직이지 않기(밀어붙이기)·근거를 따라가기·관점을 틀어 흔들기 중 하나로 의도를 정한다. 이유 없는 계속된 흔들림으로 감정을 흐리지 않는다. 감정→몸짓→결정적 한 프레임의 연쇄는 위 감정/키 비주얼 절차와 같은 것이다.

구체 카메라·수치 설계는 `camera-spatial-design`, 필요한 실제 3D 검증은 `blender-previsualization`, 시간 인과는 [26](26-state-causality-continuity.md)가 소유한다. 이 절은 Blender 실행 트리거·승인·정적/동적 검증 범위를 확대하지 않는다.

## R4. 다국어 제출문은 대응 검수문과 한 버전으로 관리한다

적용: 입력란 제약 또는 사용자가 선택한 제출 언어 때문에 번역/축약할 때만. 근거: GUIDE-01 pp27–29, 39, 64–71. 중국어·영어를 기본값으로 강제하지 않는다.

1. 한국어 등 작업자가 검토할 언어로 **사건·상태·소유·방향·정확한 대사**를 먼저 고정한다. 그 설계를 선택 제출 언어로 옮긴다. 대응 검수문은 요약이 아니다.
2. 다음을 양쪽에서 대조한다: 인원/정체성, 참조 태그, 장소와 좌우 기준, 행동 주체/소유자, 시간 구간/순서, 시도 vs 완료, 유지 vs 이동, 부정/금지, 종료 상태, 발화 원문/화자/언어, 원본 음향 사용 여부.
3. 실제 발화 대사는 번역 지시문과 분리한다. 한국어 발화 요청이면 주변 설명을 번역해도 한국어 대사 원문은 그대로 남긴다. 원문에 화자가 없으면 역할/상황만으로 화자를 확정하지 않고 `화자 미정`을 두 언어에 유지한다. 업로드 없는 번역/축약 요청의 태그는 미배정/해당 없음으로 두며 새 슬롯을 만들지 않는다. 다국어 문장이 같은 행동을 서로 다르게 지시하지 않도록 최종 지시를 하나로 만든다.
4. 제출문 수정 시 검수문도 같은 버전으로 갱신하고, 변경분만이 아닌 **최종 전체본**을 저장한다. 입력창의 이전 본문을 새 전체본으로 교체한 뒤 역할표/설정과 다시 대조한다.
5. 문자 수를 비교하면 공백·줄바꿈 포함 여부와 계산 방식을 기록하고 실제 입력창에서 한도를 확인한다. 문자 감소는 토큰·요금 감소나 결과 우월성의 증거가 아니다. 책의 특정 파일 길이를 다른 프로젝트의 압축률로 재사용하지 않는다.
6. 제목용 대괄호, 연기 메모 괄호, 환경음 묶음, 실제 업로드 태그, TTS 감정 큐, IPA를 서로 다른 층으로 구분한다. 색/괄호 자체는 범용 API 문법이 아니다. 음성창에는 발화문과 **선택 모델이 실제 지원하는 큐만** 전달한다. IPA/태그가 낭독되거나 무시되면 미지원/실패를 기록한다.

7. 부정문은 필요한 금지를 유지하되 **실제로 확인할 긍정 상태**로 보완한다. ‘배경 바꾸지 마’와 함께 유지할 랜드마크/구조/위치를, ‘손 오류 금지’와 함께 잡기→놓기의 순서·최종 소유·수량을 적는다. 부정문을 전부 제거하거나 모델의 준수를 보장한다는 뜻은 아니다(GUIDE-01 p67).
8. 입력이 과밀하면 **반복 형용사 제거→참조 역할/행동 타임라인 중복 제거→같은 구간의 카메라 지시 충돌 해소→필요 시 완결된 행동 단위로 분할 제안** 순으로 검토한다. 인물·장소·현재 상태·핵심 행동·끝 상태·필수 대사는 보존한다. 번역으로 길이만 줄이거나 시간표를 넣는 것으로 불가능한 동시 행동을 해결했다고 하지 않는다. 분할은 승인된 샷 수/길이를 자동 변경하지 않는 제안이다(GUIDE-01 p77).

검수 전 번역은 `provisional`; 번호/완료/부정 조건이 다르면 유창해도 통과가 아니다. 이름·발음은 승인 근거를 보존하며 미정 발음을 임의로 만들어 넣지 않는다.

## R5. 새 생성·부분 수정·프리비즈 참조·실제 확장을 구별한다

적용: 영상 실행 설계 또는 기존 클립의 후속 작업. 근거: GUIDE-01 pp19–22, 67, 72–77. 실제 기능 확인과 별도 실행/비용 승인은 [24](24-production-execution.md)를 따른다.

| 목적 | 경로 | 필요한 확인 |
|---|---|---|
| 새 앵글/독립 클립 | 새 생성, 필요 시 직전 상태 참조 후 편집 연결 | 첫 상태·끝 상태·채택 구간 |
| 카메라/블로킹을 전달 | 프리비즈 참조를 사용하는 새 생성 | 외형/직전 상태/카메라의 속성 분업 |
| 기존 연기/카메라를 살리고 국소 변경 | 실제 지원되는 부분 수정 | 수정 원본·범위·보존 항목·구간별 전후 비교 |
| 좋은 끝에서 같은 흐름을 연장 | 실제 Extend 모드 | 원본 테이크·끝 상태·원본 포함 여부·접합부 |

‘이어줘’ 문장, 마지막 프레임 첨부, 이전 영상의 참조 입력만으로 실제 Extend 사용을 주장하지 않는다. 기능이 없으면 새 생성+편집을 별도 대안으로 제시한다. 프리비즈 입력도 실제 확장과 다르다.

확장 전 **채택된 실제 마지막 구간**을 열어 인물/위치/자세/시선/의상/소품 손/진행 방향/카메라/음향을 기록한다. 계획과 다르면 오류 수용·수정 여부를 먼저 결정한다. 잘못된 끝을 확장해 고착시키지 않는다. 새 지시는 완료 행동의 재연이 아니라 그 이후 변화부터 쓴다.

결과는 원본 포함 전체 파일인지 추가 구간만인지 확인한 뒤 편집한다. 원본을 두 번 붙이지 않는다. 접합부를 정속·프레임 단위·청취로 대조해 자세 초기화, 완료 행동/대사 반복, 크기/소품 손/광원/배경 변화, 진행 역전, 음악/잔향 점프를 검사한다. 확장마다 새 테이크로 보존하며 원본 통과를 후속 구간의 자동 통과로 쓰지 않는다.

부분 수정은 ‘마스터→변경 항목/범위→유지 항목→성공 조건’으로 작성하고 **수정 영역 밖의 얼굴·동작·타이밍·음향까지** 전후 비교한다. 보존 문장·Edit 기능명은 실제 보존의 증거가 아니다.

<a id="dialogue-repair"></a>
## R6. 원래 연기를 보존하는 최소 발음 교정

적용: 영상/연기는 적합하고 발음 일부가 틀린 실제 음성이 있을 때. 근거: GUIDE-01 pp94–99. 보이스 선택·권리/동의·음성 실행·예산·청취의 정본은 [22](22-dialogue-lipsync.md)다. **복제는 기본값이 아니며 요청·권리 근거 없이 하지 않는다.**

1. 실제 청취 또는 귀속된 사용자 보고를 구분해 원문·들린 오류·타임코드·살릴 음색/숨/억양/감정·보이는 입을 표시한다. 못 들었으면 발음/감정 판정은 `unverified`다.
2. 최소 교체 단위를 고른다: 단어가 독립하면 단어, 받침·연음·호흡이 이어지면 주변 어절/짧은 구절. 음절 하나를 무조건 잘라 붙이지 않는다. 문장 리듬 자체가 깨졌으면 구절 단위, 시각적 입 불일치가 크면 커버리지나 해당 짧은 영상의 재작업을 비교한다.
3. 기존 승인 보이스를 우선 사용한다. 요청된 복제만 깨끗한 단일 화자·목표 톤의 사용 허가 샘플을 준비하고 현재 서비스의 실제 길이/형식을 확인한다. 같은 짧은 녹음을 반복하거나 스테레오로 복제해 최소 길이를 채우지 않는다. 공급자/웹 UI/API/모델의 다른 이름·태그·최소 시간을 혼용하지 않는다.
4. 승인된 범위 안에서 동일 문구·보이스에 지원되는 감정/발화 큐 등 주요 변수 하나를 바꿔 후보를 비교한다. 새 음성이 단독으로 멋진지가 아니라 원본 문장에 붙어 같은 인물이 이어 말하는지가 기준이다. Voice Changer만으로 틀린 단어가 자동 교정된다고 하지 않는다.
5. 원본을 보존하고 교정 오디오를 별도 트랙에 배치한다. 파형과 실제 청취로 자음 시작·받침 꼬리·들숨이 안 잘리는 경계를 찾는다. 길이가 다르면 무조건 시간 압축하지 말고 짧은 구절 재생성을 비교한다.
6. 음량·음색 밝기·공간감·잔향을 맞추고 짧은 크로스페이드를 비교한다. 고정 밀리초를 모든 접합에 강제하지 않는다. 대사/환경/음악/SFX는 가능한 한 분리하고 혼합 원본이면 음악·노이즈의 접합 점프도 듣는다.
7. **교체 구절→앞뒤 한 문장→장면 전체 믹스→영상과 입/감정** 순으로 재검수한다. 단어 정확도만으로 완료하지 않는다. 입이 보이지 않으면 해당 싱크는 이유 있는 N/A, 보이는데 검사 불가면 `unverified`다.
8. 원본 음성·승인 보이스/샘플·교정 텍스트/큐·채택 오디오 ID/버전·원본/타임라인 위치·실제 청취 범위와 미해결 항목을 기존 연기/편집 artifact에 연결한다. 변경 오디오에 종속된 자막·립싱크·타이밍을 재검토하고 새 승인 원장은 만들지 않는다.

<a id="usable-ranges"></a>
## R7. 전체 클립 판정과 채택 구간을 분리한다

적용: 생성 QA·재작업·편집·운영 회고. 근거: GUIDE-01 pp90–93, 98–101.

- 정속 전체 재생, 중요한 접촉 전후의 연속 슬로/스텝, 실제 편집 순서 재생을 구분해 검사한다. 세 장의 스틸만으로 전체 동작을 통과시키지 않는다. 관찰과 원인 가설은 별도다.
- 보고에는 원본 파일/버전·원본 기준 in/out·FPS/PTS 또는 시간 basis·사용 가능한 사건·빠진 필수 사건·전체 클립 판정·선택 구간 판정·편집 후 판정을 적는다. 타임라인 프레임과 원본 프레임이 다르면 둘을 구별한다. 해당 검사를 안 했으면 `unverified`이지 pass가 아니다.
- 좋은 앞 구간이 있어도 끝에 필요한 소유 이전이 없으면 전달 샷 전체는 실패다. 인서트·편집으로 보완하면 그 사건이 실제 최종 순서에서 읽히는지 다시 본다. 미감 평균 점수로 신원 오류·복제·틀린 화자·불가능한 동선을 덮지 않는다.
- 재작업은 **관찰→원인 가설→단일 주요 변경→보존 조건→성공 기준→실제 결과**를 기존 `generation_attempts`/QA에 기록한다. 얼굴/의상은 에셋·참조, 공간 모순은 공간 명세, 과밀 동작은 샷 설계, 발음은 음성, 단순 색차는 피니싱으로 돌아간다. 관측 근거 없이 원인을 확정하거나 모델 교체부터 하지 않는다.
- 반복 실패 시 접촉 인서트·동작 분할·단순화·다른 확인된 실행 경로를 비교한다. 책의 ‘세 번’은 운영 예일 뿐 기본 retry_budget이 아니다. 승인된 횟수·비용·시간 상한을 우선한다.
- 요청된 비용/효율 회고에만 **생성 총초수와 최종 채택 초수**를 나눈다. `채택 1초당 비용 = 명시한 포함 범위의 실제 비용 / 최종 편집에서 채택한 초수`. 같은 소스 구간을 단순 반복한 러닝타임은 중복을 밝혀 실제 확보 분량과 구분한다. 이미지·구독 배분·편집 노동 포함 여부, 통화·기간·요금/무료 크레딧 사용을 명시한다. 0초면 비율은 N/A(채택 없음), 지출 미확인이면 미산정이다. 견적과 실제 비용을 섞지 않는다.
- 재개 패킷은 새 원장이 아니라 기존 기록의 조회/인계다: **그때 넣은 것→실제로 나온 것/채택 범위→이번에 바꿀 것/보존할 것→다음 작업/미해결 승인**. 최신 버전 숫자만 보지 않고 변경 이유와 실제 원격 작업 상태를 확인한다. 이력은 `recording-production-history`, 정본 쓰기는 기존 조정자가 소유한다.

## R8. 회차의 결과와 출력 파일의 완료를 확인한다

적용: 사건 중심 단편/연속형 회차 또는 실제 납품. 근거: GUIDE-01 pp9–12, 98–101.

- 시리즈의 큰 목표 / 여러 회차의 문제 묶음 / 이번 편의 사건을 나눈다. 사건 중심 회차는 ‘목표→장애→인물다운 선택→달라진 상태→남은 관계·지식·문제’를 확인한다. 단순히 다음 편을 위해 행동 직전에서 끊고 이번 사건의 보상을 잃지 않았는지 검토한다. 의도된 직렬 구성과 비서사 형식에는 독립 완결을 강제하지 않는다.
- 목표 길이는 사용자 조건을 우선하고 고정 90초/인물 수/장소 수/구간 배분을 강제하지 않는다. 승인된 임시 음성+콘티가 실제 존재하면 재생해 측정한다. 문서만 있으면 길이는 `estimated`; 길다고 감정의 쉼부터 자르거나 전체 음성을 배속하지 말고 중복 설명/반응부터 비교한다.
- 편을 **관객이 알게 되는 정보가 바뀌는 지점**으로 구간화한다. 구간을 나눌 때마다 무엇이 새로 공개되는지 적고, 그 변화가 없으면 구간을 나누지 않는다. 참고한 길이 예시(예: 90초 기준 3구간)는 방법이 아니라 한 작품의 관찰이며 그대로 채택하지 않는다.
- 편집은 사건·소유·동선 연결을 먼저 확인하고 음향으로 결함을 덮지 않는다. 원본 발화·실제 음성·자막을 나란히 대조해 인명·고유명사·말투/조사·읽는 시간·반응보다 이른 정보 공개를 검사한다. 자동 전사는 초안이다.
- 실제 **내보낸 파일 자체**를 열어 전체 재생·첫/끝·중간 끊김·대사/자막/오디오·목적지 크롭을 확인한다. 가로·세로는 각 파일에서 손/접촉/자막/UI 가림을 따로 본다. 업스케일은 없는 디테일 복구 증거가 아니다.
- 무음 오류는 타임라인 mute/출력 오디오/재생기, 검은 화면은 원본 연결/출력 범위 등 실제 원인을 분리한다. 인코딩/편집 오류 때문에 모든 영상을 재생성하지 않는다. 수정 가능한 프로젝트·원본 위치·자막·필요 오디오·버전별 출력도 연결한다.
- 준비 문서, 제출, 파일 수신, 실제 시청/청취 검수, 편집 배치, 출력 파일 검사, 사용자 수락, 게시는 서로 다른 상태다. 기존 enum을 재정의하지 않고 실제 검사 범위와 미검증을 보고한다.
