# ChatGPT Work workspace integration

Apply this adapter only when the current runtime explicitly identifies itself as ChatGPT Work and the capability/path required for the selected task is actually available (for example, `/root/.codex/skills/remote-skills` for sibling resolution, `image_gen.imagegen` for image work, or the remote Documents/Library integration when file storage is needed). Linux alone does not qualify. Otherwise ignore the bullets below and follow the package-native instructions for the current host; do not substitute a different host's adapter.
- Resolve a sibling skill by its exact `name` frontmatter under `/root/.codex/skills/remote-skills/*/SKILL.md`; installed directory names may differ from skill names. Resolve sibling links/resources against that directory. Run `scripts/...` relative to the skill directory, never the current project directory.
- Use the available built-in image generation tool (`image_gen.imagegen`) for image requests and edits. It replaces this package's unavailable `codex-imagen` CLI dependency in this workspace. Read the installed imagegen skill when needed. Preserve supplied references; inspect local images before edits. Do not require a CLI login or quote for the built-in tool. Returned generated images are displayed and saved automatically; do not download or reconstruct them only for display/storage.
- For Higgsfield execution, use the installed official Higgsfield plugin skill matching the requested task and its MCP tools first. Upstream CLI recipes are reference material, not a required runtime or proof of current models, pricing or support. Follow the selected plugin's current input/output, consent and spend contract. Use Sites skills for ordinary requested website builds. Preserve package craft and canonical IDs without inventing unsupported tool equivalence.
- The remote container's Documents folder is not the user's Windows Documents. For actual file production, choose a scratch project root explicitly via `production_history.py init --project-root <absolute-project-root>`, keep chronological history there, and persist requested deliverables and necessary project checkpoints using the installed Library skill. Include history/project manifests when delivering a complete package. Reuse an explicitly selected project root. Chat-only work creates no files/history. Never save production artifacts in the skills checkout. Generic files require actual Library saving; generated-image automatic saving is the stated exception.
- Existing user authorization carries across stages. Perform necessary reversible preparation and authorized execution without repetitive approvals. Ask only when a concrete unresolved choice or the selected tool's actual approval requirement remains; an upstream blanket stage gate alone does not require renewed approval. User review, technical QA and public publication remain distinct.
- Discover only dependencies needed for the selected task. Report missing capabilities accurately; installation of these instructions does not install Blender, FFmpeg, model weights or external credentials. Do not autonomously invoke subagents except where the user or applicable skill explicitly authorizes them.
