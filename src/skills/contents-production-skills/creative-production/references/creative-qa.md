# Deliverable verification

Apply only the requested output's checks. Record actual evidence and unverified conditions separately. Draft, generated file, inspection, user acceptance and publication are different states; a validator/model judgment is not user approval or legal clearance.

## Text and planning

- Show the requested artifact in the requested language/format, not merely a completion report.
- Trace factual claims to supplied/verified sources; separate arithmetic, interpretation, fiction and proposals. Unknown causes and outcomes stay unknown.
- Preserve fixed facts, characters/products, continuity, approved direction and exclusions across requested stages.
- Check specified timing allocations sum to the requested duration without presenting estimates as frame-accurate execution.
- Apply narrative/commercial structure only when it fits the brief. Omit inapplicable characters, CTA, extra formats and unrequested stages.
- Saving requested text does not imply images, video, project state or publication.

## Cross-stage preproduction corrections

For a requested full synopsis/script/storyboard package, the coordinator runs this text QA before requesting final panel images:

- Compare the current brief and source/approval versions across synopsis, screenplay, and technical storyboard. Preserve every required fact/event, cause→choice→result transition, reveal order, character/prop state, and applicable dialogue/caption/audio constraint. Map every synopsis beat through scenes, shots, and panels; identify omissions, duplication, contradictions, and unexplained transitions by stable IDs/source location.
- Check scene/shot/panel durations against the supplied total and frame rate; allocations must cover the requested timeline without gap, overlap, or an invented measured runtime. Keep proposed/estimated timing and spatial/lighting values labeled as such.
- For each blocker, record its observable evidence, audience/production consequence, smallest in-scope correction, preserved approved material, affected artifact/version dependencies, and a checkable reinspection criterion. Apply only authorized changes, advance affected artifact versions, mark only true dependents stale, and repeat the affected checks before continuing. A consequential story/direction change stays proposed or blocked pending authorization.
- When correcting generated imagery, separate identity/style/location references from pose/action authority and state what each reference proves. Do not keep a rejected image as the pose base by default; exclude failed pose authorities and use an accepted, purpose-matched reference or measured geometry. Bound the first correction as a single-output probe with explicit source versions and acceptance checks; if it fails, diagnose the reference/renderer path before further calls. If it passes, apply the confirmed correction only to affected dependents and preserve accepted images.
- After actual image generation and storyboard-sheet extraction, repeat the image-only narrative/continuity review across every clean panel in story order. The complete visual criteria and KEEP/FIX/unverified report are owned by [storyboard contract](../../video-production-assets/references/storyboard-contract.md#5-이미지-단독-스토리텔링-게이트); the structural validators do not replace this inspection. Correct permitted failures minimally and reinspect affected images plus the complete story order.
- Report preproduction readiness separately from user review acceptance and video execution approval. Missing runtime, asset-gate, spatial/Blender, image, verification, or named-desktop-app prerequisites remain explicit blockers; do not manufacture a pass or stop other reachable work. A permitted cross-tool substitute (for an absent Adobe/TouchDesigner/Resolve app, the ArtCraft counterpart in [production-routing-optional.md#desktop-app-fallback-artcraft](production-routing-optional.md#desktop-app-fallback-artcraft)) changes which tool runs, not whether the result was verified, and never applies where no counterpart exists.

## Actual audio/video

- Confirm the real files and canonical IDs/versions; distinguish failed or missing outputs from successful ones.
- Listen to audio for script fidelity, pronunciation, noise, pacing and sync.
- Inspect actual video frames and transitions for temporal artifacts, subject/product continuity, camera action, unwanted objects and intended composition.
- Probe duration, frame rate, aspect/resolution, encoding, captions and audio sync with available media tools.
- Compose critical words, logos, prices and legal text deterministically when needed; check actual readability.
- Check the requested delivery format and destination-specific conditions. A preview/API success is not a final encode.
- When reference intent or project style is a requested criterion, use [production QA](../../video-production-assets/references/12-qa.md#레퍼런스-의도-대조-해당-작업만) for evidence-backed qualitative comparison and requested retrospectives.

## Blender/3D and web

- Open/render the actual Blender scene when that is the output. Check intended camera, scale, blocking and geometry against the source specification.
- For pose-only feasibility verification, preserve fixed model parameters across poses, including segment lengths and parent-local joint attachments; compute world anchors from each actual parent pose transform. Allow articulated parents (such as a clavicle) to move within the model contract: attachment invariance is parent-local, not fixed world Z. Numeric reach/contact/clearance passes after arbitrary pose-specific model mutation or anchor relocation establish only the modified model's feasibility, not the original actor's. If the model explicitly permits deformation, verify against that declared model contract.
- Inspect scripts before execution and preserve unrelated files/scene objects. A mathematical projection or proxy is not photoreal/final-media QA.
- Load actual exported assets in the requested surface; check materials, memory/geometry budgets, interactions and relevant fallbacks.
- For actual web deliverables, inspect the rendered browser route, accessibility, keyboard/focus, mobile/loading/error/reduced-motion behavior and applicable performance measures. Source inspection alone is insufficient.

## Provenance, authorization and delivery

- Record relevant source/asset/provider/model versions and actual file paths. Check selected-provider terms/rights live when required; don't claim general commercial/legal safety.
- Verify execution was within its version-bound scope and spend/retry/time caps. Changed inputs make affected approvals stale, not all project approvals.
- Keep secrets and private user sources out of published artifacts.
- Report actual exercised verification and remaining limitations. No publication or live changes from a draft-only request.
